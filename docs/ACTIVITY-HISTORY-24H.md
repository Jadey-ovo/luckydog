# 24 小时个人查询变更记录

本分支 `codex/activity-history-24h` 供审查。桌面版本号仍为 1.2.0；本轮未创建标签、安装包、Release，未部署 Sites，未合并 main。

## 生命周期

```text
创建 → open → 提前/自然截止 closed → 成功同步开奖 drawn
          ↑      │                       │
          └ 原截止时间前恢复              └ 继续抽奖覆盖最新结果
open/closed → 租约中断 interrupted（不可恢复报名或开奖）
任意状态 → 创建满 24 小时 expired，或经二次确认 clear 立即删除
```

报名截止与查询截止分别使用 join_expires / expires。心跳、恢复报名、重抽都不延长原查询期限。开奖后不再依赖租约，关闭或刷新不会删除结果；刷新仍会丢失仅存于内存的发起人管理令牌。未开奖时停止续期约 90 秒后中断；中断活动在剩余查询期内保留本人信息，不能伪装为已开奖。

清空确认明确说明链接立即失效与不可撤销。删除失败保留现有界面以便重试；404 视为服务端已不存在，可完成本地清空。二维码在报名截止后仍可用于查询，不再标为失效。

活动接口只向管理员返回完整名单与结果。参与者根据 HttpOnly Cookie 匹配数据库报名 ID，只收到本人用户名、中奖布尔值与最新时间；未参与者不收到任何姓名、完整结果或参与人数。移除后身份不再属于该活动；开奖后禁止修改名单。结果写入检查中奖 ID 来自当前名单且不重复，姓名从数据库获取。

## 异常处理与清理

首次请求完成前只展示加载，不展示截止或结束。网络错误与 404 明确区分，可重试；失败时不继续展示可能过时的个人结果。开奖同步失败保留同一结果供重试，成功前禁止继续抽奖。清空失败不丢失管理上下文。

API 在创建满 24 小时时立即拒绝访问。独立 Worker 每小时计划清理，Sites 在后续 API 请求触发清理，每个运行实例最多每小时一次。无流量时物理删除可能延后；平台备份与日志不在应用删除范围内。

新增 0004 迁移同时覆盖 Worker 与 Sites：把旧 expires 从创建 + 7 天转换为创建 + 1 天；旧中奖随机 ID 按同活动唯一姓名映射回报名 ID；已开奖结果去除在线租约。已发布迁移未改动。

旧 `/api/results` 兼容公开分享保持原短租约语义；当前在线邀请只使用 `/api/rooms`。旧 Node 对照服务不是新协议的生产入口。
